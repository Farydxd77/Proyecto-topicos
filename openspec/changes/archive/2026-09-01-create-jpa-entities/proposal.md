## Why

The backend currently has no domain model — only bootstrap infrastructure. Before repositories, services, or controllers can exist, the persistent domain objects (users, participants, groups, expenses, and their memberships) need to be defined as JPA entities so Hibernate can create and manage the corresponding PostgreSQL tables.

## What Changes

- Create 6 JPA `@Entity` classes in `com.cuentasclaras.backend.entity`: `Usuario`, `Participante`, `Grupo`, `GrupoParticipante`, `Gasto`, `GastoParticipante`, mapped exactly to the tables, columns, types, and constraints defined in `openspec/specs/data-model.md`.
- Map relationships between entities: `Usuario` 1:1 `Participante`; `Grupo.creador` → `Participante`; `Gasto.grupo` → `Grupo` and `Gasto.pagador` → `Participante`; `GrupoParticipante` and `GastoParticipante` as join entities with composite primary keys.
- Add `created_at`/`updated_at` timestamp handling on every entity that has those columns, consistent with the project convention.
- Let Hibernate (`ddl-auto=update`) generate the 6 corresponding tables in PostgreSQL from these entities with no manual DDL.

## Non-Goals

- No Spring Data JPA repositories (tracked as a follow-up change).
- No services or controllers.
- No business logic — e.g. auto-creating a `Participante` when a `Usuario` is registered, or enforcing that a `Gasto`'s pagador is a member of its `Grupo`, is documented as expected system behavior elsewhere but is explicitly out of scope here.
- No input validation (Bean Validation annotations).
- No DTOs, exception handling, or security changes.

## Capabilities

### New Capabilities
- `entidades`: The JPA entity layer for the core domain model (Usuario, Participante, Grupo, GrupoParticipante, Gasto, GastoParticipante) and the tables Hibernate generates from it.

### Modified Capabilities
(none)

## Impact

- Affected code: new files under `backend/src/main/java/com/cuentasclaras/backend/entity/`.
- New database tables: `usuarios`, `participantes`, `grupos`, `grupo_participantes`, `gastos`, `gasto_participantes` in the `cuentas_claras` PostgreSQL database (auto-generated by Hibernate on startup).
- No impact to `frontend/` or to the existing `backend-bootstrap` capability.
- `openspec/specs/entidades/spec.md` currently holds informal acceptance criteria (not yet in Requirements/Scenario format) that served as input to this proposal; this change's delta spec formalizes it into a proper main spec at sync time.
